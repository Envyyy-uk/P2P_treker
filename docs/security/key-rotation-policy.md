# Політика ротації API-ключів (Фаза 0.1, п.7)

## Правила для всіх ключів бірж

- Права: **тільки read** для MVP; trade — лише з Фази 5; **withdraw — ніколи**.
- IP whitelist увімкнено на кожному ключі.
- Окремі ключі для dev / staging / production — ніколи не переиспользовувати.
- Ключі не потрапляють у код, Git, БД у відкритому вигляді, логи
  (маскування — `backend/app/core/logging.py`).

## Ротація

1. **Термін дії:** кожен ключ живе максимум **90 днів** від дати створення.
2. **Заміна без даунтайму:**
   - створити новий ключ з тими самими правами та IP whitelist;
   - додати новий ключ у secrets manager / `.env` поряд зі старим;
   - перезапустити/переконфігурувати застосунок на новий ключ;
   - переконатися за логами/health, що новий ключ працює;
   - деактивувати старий ключ на біржі.
3. **Моніторинг:** дата створення кожного ключа фіксується в конфігурації
   (`EXCHANGES__<NAME>__API_KEY_CREATED_AT`); за 14 днів до дедлайну —
   алерт (Фаза 6), прострочений ключ — критичний алерт.

## Зберігання секретів

- Локальна розробка: `.env` (у `.gitignore`), шаблон — `.env.example` без секретів.
- Production: secrets manager (Vault / AWS Secrets Manager / Doppler тощо).
- Повідомлення про помилки не містять токенів, ключів, заголовків
  авторизації, приватних параметрів запитів.
